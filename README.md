# Dayflow — дэшборд продуктивности

Дэшборд хранит годовые, месячные, недельные и дневные цели, задачи, статусы и дедлайны. После входа данные сохраняются локально и синхронизируются с Supabase между устройствами.

## Запуск

Нужен Node.js `20.19+` или `22.12+`. Откройте терминал в папке проекта:

```powershell
npm.cmd install
npm.cmd run dev
```

Откройте адрес Vite, обычно `http://localhost:5173/`.

## Настройка Supabase

1. Создайте проект на [supabase.com](https://supabase.com/).
2. В панели проекта откройте **Project Settings → API** и скопируйте **Project URL** и **Publishable key**. В браузерном приложении используется только публичный ключ; `service_role` здесь не нужен и не должен попадать в клиентский код.
3. Скопируйте `.env.example` в `.env.local` в корне проекта и заполните значения:

   ```env
   VITE_SUPABASE_URL=https://your-project-id.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=ваш-публичный-ключ
   ```

   `.env.local` автоматически исключён из Git. Vite читает переменные с префиксом `VITE_` и включает их в клиентскую сборку, поэтому здесь допустим только публичный publishable/anon key.

4. В Supabase откройте **SQL Editor → New query** и выполните миграции в порядке:
   - `supabase/migrations/20261023000000_dashboard_sync.sql`
   - `supabase/migrations/20261024000000_workspaces.sql`
   - `supabase/migrations/20261025000000_workspace_task_comments.sql`
   - `supabase/migrations/20261026000000_friends.sql`
   - `supabase/migrations/20261027000000_workspace_friend_invites.sql`
   - `supabase/migrations/20261028000000_workspace_history.sql`
   - `supabase/migrations/20261029000000_workspace_roles.sql`
   - `supabase/migrations/20261030000000_workspace_archive.sql`
   - `supabase/migrations/20261031000000_friend_lookup_email_fix.sql`
   - `supabase/migrations/20261032000000_usernames.sql` (уникальные username, таблица `profiles` с RLS)
   - `supabase/migrations/20261033000000_task_recurrence.sql` (повторяющиеся задачи: колонка `tasks.recurrence`, обновлённый `sync_dashboard`)
   - `supabase/migrations/20261034000000_task_reschedule.sql` (история переноса: `moved_from`, `moved_at`, `move_count`, обновлённый `sync_dashboard`)
   - `supabase/migrations/20261035000000_task_reminders.sql` (настройки напоминаний на личных задачах, обновлённый `sync_dashboard`)
   - `supabase/migrations/20261036000000_signup_username.sql` (создаёт профиль с уникальным username при регистрации)

   Первая миграция создаёт личные таблицы и атомарную RPC-синхронизацию. Миграции пространств добавляют отдельные таблицы общих целей/задач и не переносят и не меняют существующие личные записи. Последняя миграция добавляет архивные отметки и RPC для архивирования и восстановления общих записей.
5. В **Authentication → URL Configuration** укажите адрес приложения в **Site URL** и добавьте его в **Redirect URLs** (например, `http://localhost:5173/**`). Если подтверждение почты включено, подтвердите адрес из письма перед входом.
6. Перезапустите Vite после создания `.env.local`: `npm.cmd run dev`. Зарегистрируйтесь или войдите в интерфейсе дэшборда.

При регистрации теперь обязательно задаётся уникальный username. Чтобы профили создавались при подтверждении аккаунта, выполните миграции `20261032000000_usernames.sql` и `20261036000000_signup_username.sql` (все миграции запускаются по порядку). Изменение существующего username доступно через кнопку настроек рядом с email в шапке.

Пользовательские таблицы имеют `user_id` и политики RLS на чтение, добавление, изменение и удаление. Внешние ключи не позволяют связать задачу или подцель с записью другого владельца. RPC-синхронизация выполняется от имени вошедшего пользователя и проверяет ожидаемую ревизию; конфликт между устройствами не перезаписывает сервер молча. Локальные копии хранятся с ключом пользователя; старые несвязанные с аккаунтом локальные данные один раз закрепляются за первым вошедшим пользователем в этом браузере и не предлагаются следующим аккаунтам.

Пространства и общие записи защищены отдельными политиками RLS: читать и изменять их могут только участники. Комментарии к общей задаче доступны участникам её пространства, автор может изменять и удалять свои комментарии, владелец пространства может удалять любой комментарий. Назначение ссылается только на участника того же пространства; при выходе или удалении участника назначение автоматически сбрасывается через `ON DELETE SET NULL`. Личные таблицы задач остаются отдельными, комментарии доступны только через таблицу общих задач. Изменение ролей, создание/удаление пространства, приглашение и принятие приглашений выполняются проверяемыми функциями базы данных; клиент не получает `service_role` и не может напрямую назначить себе членство или роль. Приглашение вводится по email существующего пользователя и появляется у него во вкладке **Пространства** после входа. Email-уведомления не отправляются: для них отдельно понадобится настроить почтовый сервис и серверную функцию, секреты которой нельзя размещать в клиентском приложении. Список пользователей Supabase в интерфейсе не раскрывается.

Архив распространяется только на общие цели и задачи рабочего пространства. Архивировать и восстанавливать записи могут владелец и администраторы; это проверяет база данных. Архив сохраняет саму запись, связи, комментарии и историю, а также идентификатор архивировавшего и время. В пространстве есть отдельный поиск и фильтры по типу/статусу, участнику и дате архивации. Личные цели и задачи этой функцией не затрагиваются.

В активном пространстве командный обзор строится только по общим записям Supabase за выбранный период. Каждая неархивная задача учитывается один раз по её дате: процент выполнения — выполненные задачи, делённые на все задачи периода. Для непересекающихся статусов задача считается либо выполненной, либо просроченной незавершённой, либо активной («В процессе»), либо ожидающей выполнения. Просрочка определяется по сроку, а если он не задан — по времени задачи или концу указанного дня в локальном часовом поясе браузера. Прогресс цели вычисляется по связанным с ней общим задачам и подцелям.

Новые цели и задачи создаются из личного дэшборда с явным выбором **Личное** или конкретного пространства. Существующая личная задача переносится/копируется только через отдельное действие с подтверждением; при переносе личная запись удаляется лишь после сохранения общей. Общие записи также можно создавать непосредственно в открытом пространстве. Участники могут редактировать общие данные, а задачи назначать участникам. Изменения общих данных обновляются в открытом пространстве в реальном времени при включённом Supabase Realtime.

## Перенос и работа без сети

При первом входе существующие локальные данные не отправляются автоматически. Если локальные данные найдены, интерфейс предложит импортировать или объединить их с серверными. Если записи с одинаковым ID различаются, сохраняются обе версии: локальной записи назначается новый ID, а связи целей и задач обновляются. Если выбрать серверную версию, локальная копия предварительно сохраняется в браузере как резервная.

Изменения сначала сохраняются в локальной копии пользователя. При отсутствии сети они помечаются как ожидающие синхронизации и отправляются после восстановления подключения. Если сервер изменился параллельно, пользователь выбирает серверную версию либо явно подтверждает замену сервера текущей локальной версией.

## Просроченные задачи и перенос

Вкладка «Просрочено» в панели задач показывает личные незавершённые задачи, срок которых (дедлайн или дата) уже прошёл. Задачу можно перенести на завтра, на понедельник следующей недели или на выбранную дату, либо отметить несколько и перенести разом: перед этим показывается число задач, а после — кнопка «Отменить перенос». Перенос меняет дату существующей задачи (копии не создаются), запоминает прежнюю дату и число переносов. Дедлайн сдвигается, если оказался раньше новой даты; связь с целью снимается, если новая дата вне срока цели. Для повторяющихся задач переносится только выбранный экземпляр (за последние 30 дней), правило не меняется. Задачи рабочих пространств сюда не входят.

## Поиск, фильтры и сортировка задач

В таблице задачи ищутся по названию и заметкам. Комбинируемые фильтры позволяют выбрать статус (все, активные, выполненные, просроченные), приоритет, цель, наличие срока и область дат — текущий период или все даты. Для повторяющихся задач в режиме «Все даты» учитывается скользящий год истории, чтобы не создавать неограниченное число экземпляров. Активные фильтры видны отдельными метками; их можно снимать по одному или сбросить вместе с поиском. Заголовки названия, даты/времени, приоритета и статуса сортируют в обе стороны с индикатором направления. Фильтры хранятся только в памяти страницы.

## Аналитический обзор

Панель «Прогресс» считает личные задачи за неделю или месяц относительно выбранной даты. Запланированной считается каждая задача с датой в периоде, а повторяющиеся задачи учитываются по отдельным экземплярам. Процент — выполненные со статусом «Выполнено» от всех запланированных задач. Просроченные — незавершённые задачи с прошедшим дедлайном (или датой задачи, если дедлайна нет). Переносы считают записи/экземпляры, перенесённые в период по сохранённым данным. Прогресс целей рассчитан по связанным задачам в том же периоде и целям, пересекающим его. Сравнение показывается, только если есть данные за предыдущий такой же период. Все календарные границы используют локальные даты; для пустых периодов и малой выборки интерфейс сообщает, что вывод основан на доступных задачах. Статистика вычисляется из уже существующих данных, миграция не нужна.

## Напоминания

У личной задачи можно выбрать «Без напоминания», «В назначенное время» или за 5/15/30/60 минут либо за день до срока. Временем считается дедлайн, а при его отсутствии — указанное время задачи; без времени напоминание не включается. Разрешение браузера запрашивается только по нажатию «Включить уведомления». Уведомления браузера и список ближайших напоминаний работают, пока приложение открыто; фоновой доставки после закрытия сайта нет. Глобальный переключатель хранится локально для аккаунта и текущего браузера, а правило задачи — в Supabase с RLS личной таблицы. Общие задачи пространств пока не включены в напоминания. Для новой схемы нужно выполнить миграцию `20261035000000_task_reminders.sql`.

## Календарь

В панели «Задачи» переключатель «Таблица / Календарь» показывает личные задачи по месяцу, неделе или дню (переходы ‹ ›, «Сегодня», выбор даты). Задачи со временем стоят в часовых слотах дня, без времени — в блоке «Без времени». Задачи на одно время показываются обе с значком конфликта. Длительность не хранится, поэтому задача занимает слот начала. Перенос перетаскиванием выполняется после подтверждения; повторяющиеся задачи открываются для правки серии. Миграция не нужна.

## Загрузка в GitHub или другой Git-хостинг

Создайте пустой репозиторий на выбранном Git-хостинге. В терминале, открытом в папке `productivity-dashboard`, проверьте исключение `.env.local`, затем добавьте файлы и привяжите удалённый репозиторий:

```powershell
git check-ignore .env.local
git init -b main
git add .
git status --short
git commit -m "Prepare productivity dashboard"
git remote add origin https://github.com/ВАШ-АККАУНТ/ВАШ-РЕПОЗИТОРИЙ.git
git push -u origin main
```

Перед коммитом убедитесь, что `.env.local`, `node_modules` и `dist` не отображаются среди добавляемых файлов. В репозиторий включайте `.env.example`, но никогда не используйте `git add -f` для `.env.local`. Если GitHub попросит войти, используйте его обычную авторизацию или Git Credential Manager.
